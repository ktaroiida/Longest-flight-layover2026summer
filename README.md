# AIR ROUTES — 日本の空は、どこまでつながっているのか？

国内航空路線のネットワーク・最長片道・最多乗継を可視化するWebアプリ。React / TypeScript / Vite / MapLibre GL JSで、空港から国内路線網が大圏航路に沿って広がります。地図・空港・路線・ライブラリはローカルに収録し、地図タイルAPIやバックエンドを使用しません。外部公開・GitHubへの送信はまだ実施していません。

## すぐ見る

`python3 scripts/make-standalone.py` で生成する `航空路線ビジュアライザー_Phase1.html` は、JavaScript・CSS・地図・空港・路線を収録した単一ファイルです。WebGL2が利用できる現在のブラウザーで開いてください。ブラウザーのローカルファイル制限で動作しない場合は、以下のローカル実行を使用してください。単一HTMLの画面操作は今回未確認です。

## ローカル実行

Node.js 22.12以上（または24 LTS）とnpmを使用します。このプロジェクトのルートディレクトリで実行してください。

```sh
npm ci
npm run dev
```

表示されたURL（通常 http://127.0.0.1:5173 ）を開きます。

```sh
npm test
npm run build
npm run preview
```

`dist/` はビルド済みの静的サイトです。`dist/index.html` を単独で移動せず、assetsと一緒に配置してください。

単一HTMLを再生成する場合：

```sh
npm run build
python3 scripts/make-standalone.py
```

出力先はプロジェクトの1階層上です。

## 使い方

1. 空港名・IATA・ICAO・英語名で検索し、プルダウンで選択するか、地図の空港をクリック。
2. ANA・JAL・その他の運航会社を複数選択。「すべて選択」も使用可能。
3. 「再生する」で1段階目から路線が伸び、到着すると点が光る。
4. 一時停止・再開・リセット・速度変更が可能。
5. 初期選択は羽田。鳥取から試す場合は出発空港で鳥取を選択。
6. 「データと出典」で対象範囲・路線の方向・運航会社・ブランド・有効期間・資料ページを確認。

スマートフォン向けには上部の操作パネルを折りたたむCSSを実装しています。

## 実装範囲

実装済み：暗色の日本地図、空港選択、複数会社の選択、BFSの段階展開、球面補間、区間重複の除去、到着点の強調、再生・停止・再開・リセット・速度変更、地図移動・ズーム・出発空港フォーカス・全体表示、到達空港/区間/段階カウンター、路線別出典、レスポンシブCSS。

対象を全国台帳の **88地点（85空港・3ヘリポート）、518方向別レコード・259物理区間** へ拡張しました。通常表示（2026/10/13基準）はANAが55空港・123区間、JALが64空港・153区間です。会社のチェックを変えると対象空港だけを表示し、両社選択では和集合を表示します。対象外になった出発空港は選択を維持して注意文を出します。再生はその出発空港から到達できる範囲を探索します。

五島福江・壱岐・天草・奄美などを含め、既存台帳にある全地点を収録。ANA/JALは路線単位のブランド所属フラグで判断し、提携会社の全路線を無条件にブランド所属にしません。その他の会社は別の選択画面にまとめ、左パネルを長くしません。

期間外・運休・直行便未確認として保守除外した区間は通常表示から除きます。「期間限定路線も含める」で記録済みの季節便を表示できます。これは異なる期間の和集合であり、同一日に利用できることを意味しません。運休・直行便未確認の区間はこの切り替えでも描画しません。

この「全国版」は**全国台帳全体を表示する版**です。2026/10/13の全就航便・全運航会社・全運航日を手作業で照合した完全保証版ではありません。会社ごとの対象空港数は収録データ内の件数です。未照合区間を含む点は画面・データ・路線別出典にも明記しています。

未完了：全路線の日付別ダイヤ・方向別運航・実運航会社の完全照合、世界路線版、URL共有、動画出力。予約・空席確認は仕様書の初期対象外です。

- JAL/その他の路線図区間は双方向のネットワークとして採録し、`directionVerified:false` を記録。これは方向別ダイヤを確認したことを意味しません。`directionVerified:true` はその方向のANA公式抽出があることを示し、同じ区間の全会社・全日付の照合済みを意味しません。
- 実運航会社が未特定のJALグループ区間は `operators:[]` とし、具体的な会社名を推測して補いません。その他の会社選択は確認・採録された実運航会社の区間のみです。
- 基準・編集日：2026-10-13。旧全国台帳は2026-10-07の研究資産、ANA資料と除外区間の調査は2026-10-12。JAL公式コードシェア一覧は2026-10-13に確認。資料間の基準時点が異なるため、全件最新確認済みとは扱いません。
- `status` は `published-network` / `seasonal` / `suspended` / `unconfirmed`。確認済みの方向制限（与論→奄美など）を保持し、運休は除外。記録されていない運休・期間変更の有無は全件確認未完了です。
- 空港座標・英語名・コード：[OurAirports](https://ourairports.com/data/)。2026-10-13取得。Public Domain。ICAOや所在地が欠ける場合はnullで保持します。

## 計算・描画

`src/graph.ts` はUIから独立しています。方向別の隣接リストを作り、出発空港からBFSで探索します。ブランドの所属は路線単位のフラグで決定し、提携会社の全路線をブランドに含めません。描画の重複除去には順序を無視した内部空港IDの組を用います。逆方向のレコード自体は探索時に保持します。

球面の座標ベクトルを補間し、大圏航路を64分割。既描画の線は残し、現在の段階の各線を同時に伸ばします。線の全座標は再利用し、表示中の部分をSVGのパスとして描画します。地図の移動・ズームはMapLibreのカメラを使い、輪郭と路線は同じ投影でSVGに描くため、ローカルファイルのGeoJSON worker描画に依存しません。速度変更は次のフレームから反映し、一時停止でrequestAnimationFrameを解除。バックグラウンドの長い間隔で急に完了しないよう1フレームの進行を制限します。

空港再訪禁止の最適経路とは異なり、BFSでは到達済み空港間の区間も1度表示します。ネットワーク全体を見せるための仕様です。

## 最適経路JSONの仕様

`src/types.ts` の `PathResult` と `public/data/path-results.schema.json` を参照。ANA/JAL/ALL × legs/distanceの6種類を `public/data/path-results.json` に収録済みです。

- 内部空港ID・方向別路線IDの順序リスト。
- 再訪なし、出発/到着は固定なし、時刻表制約なし。
- `optimal` は最適性が証明された場合のみ。未証明は `best-found`。
- 計算対象範囲、基準日、ソルバー・バージョン・gapを記録。
- 路線ごとの大圏距離を合計し、ブランド重複を水増ししない。

## ネットワークを見やすくする表示調整

羽田発ANAの3段階は正常です。第1段階は40区間・40新規空港、第2段階は82区間・14新規空港、第3段階は到達済み空港間の1区間。羽田を含む55空港すべてに到達しています。BFSの段階はネットワークの深さであり、長い旅程の便数とは異なります。

- 段階内で路線の描き始めを少しずつずらし、既描画の線は徐々に暗く細くする。線は消さず、最新の区間を主役にする。
- 1段階は基準速度で2.8秒。速度設定・一時停止時の進捗に連動して線の減光も停止する。
- 空港の点は、選択会社内の重複を除いた接続先数で3.5〜11.5pxに変える。便数ではなく接続する空港数によるサイズ。
- 接続先が15以上の空港は全体表示でも名前を表示。小さな空港はズームレベルに応じて表示し、重なりを避けて左右・上下へ配置。選択中の空港名は優先し、隠れている名前もホバー・キーボードフォーカスで表示。
- 自動テスト8件成功。段階内の時間差、完成時の全区間描画、減光、サイズの重複除去、ズームでのラベル表示、衝突回避を検証。実画面での見た目の再確認は未実施。

## 空港選択リストの並び

都道府県コード01〜47の順に並べ、同じ都道府県内は収録された有効な全社路線の接続先数が多い順で表示します。全社の便数集計を持たないため、便数順ではなく接続先数を代理指標として使用。同数なら日本語名順です。会社を選択するとリストの対象空港が絞られますが、順位に使う接続先数は全社共通です。

所在地はOurAirportsのISO地域コード（JP-01〜JP-47）を使用。都道府県コード表：[国土交通省](https://nlftp.mlit.go.jp/ksj/gml/codelist/PrefCd.html)。IATAのない島の地点も座標を用いて同名施設を区別し、東京都に分類しています。

都道府県の見出しと「鳥取 × ANA から試す」ボタンはユーザー指定で削除。空港の並び順は維持。

## 到着時の連続再生・始点の位置修正

段階内の路線ごとの開始遅延を廃止し、同じ出発空港の路線は同時に描き始める方式に変更。各段階の路線は同時に到着し、到着したフレームから次段階へ進むため、意図的な待ち時間を設けません。既描画路線の減光は維持しています。

空港マーカーの整数ピクセルへの丸めを無効にし、SVG路線と同じ小数ピクセル位置に合わせました。同じ空港の路線の始点座標は共通です。画面上のずれの実機再現は未確認ですが、開始時刻の意図的なずれと点の座標丸めは解消しています。

## 空港ごとの到着と必要便数（最新の再生仕様）

段階全体の到着を待つ方式を廃止しました。区間の大圏距離に比例する描画時間（短区間には最小時間あり）を使い、各空港への最初の到着時刻を計算し、その空港からの線は到着した時点で描き始めます。遠い空港への線がまだ伸びている間でも、近い空港からの再生は先へ進みます。これは演出用の時間であり、実際の飛行時間・時刻表ではありません。線の減光、速度変更、一時停止は共通の再生時計に連動します。

「探索の段階」を「全到達空港までの最大便数」に変更。出発空港から到達できる各空港へ、最短で必要な便数の最大値を表示し、乗り継ぎ回数（便数−1）を併記します。到達済み空港同士を最後に結ぶ線の段階は便数に加算しません。現在のANAデータでは羽田は55空港まで最大2便/乗り継ぎ1回、与論は55空港まで最大4便/乗り継ぎ3回です。選択会社で到達できる範囲についての指標であり、日本の全空港への到達や実際の旅程成立を保証するものではありません。

ビルド成功・自動テスト9件成功。短い区間からの次の線が長い区間の到着前に始まること、到着時刻と出発時刻の一致、全区間の終了、便数の計算を検証しました。実画面の再確認は未実施です。
